这次修改的要点
  • Llama3.1 采用模型默认采样：True / 0.6 / 0.9；Top-K 缺省为框架默认 50。
  • CodeLlama、CodeGemma、Gemma2 的官方 generation_config 未指定采样参数，按框架基础默认 False、单束贪心；表中破折号表示温度 / 截断采样过滤器不参与选择。
  • Gemma3 采用模型默认 True / Top-P 0.95 / Top-K 64，温度缺省为框架默认 1.0。
  • Qwen2.5-Coder 的温度 0.7、Top-P 0.8、Top-K 20 和重复惩罚 1.1 来自 checkpoint，而非另加一组实验调参。
  • GPT-OSS 仅温度 1.0、Top-P 1.0 作为明确作者推荐覆盖；撤去上一版推断的 Top-K=0 等覆盖，未指定项回到 checkpoint / 框架默认。其采样开启来自 checkpoint，默认思考强度 medium 保留。
  • 不继承 pipeline 或旧脚本修改后的内存配置。显式 EOS 列表保留；缺失协议 token 从干净模型配置补齐，PAD 必要时采用框架的首个 EOS 回退。
transformers_version 与实验环境

JSON 的 transformers_version 是保存配置时记录的元数据，不要求精确安装该版本。官方源码将其列为 METADATA_FIELDS，并在序列化时写入当前 __version__。应遵守模型明确的兼容要求，例如 Qwen3 的版本要求。

用户确认历史模型能正常推理，可支持其基本运行兼容性。仅凭版本与 JSON 不同，不列为缺陷或补跑理由。未来尽可能固定共同兼容的环境，真实依赖冲突再拆分；同一模型的对照保持环境一致并记录版本。本轮没有安装、升级、降级或切换任何环境。
